# Lookup tables

Inventory Kamera validates everything it OCRs against four JSON files in the `inventorylists`
folder (next to `InventoryKamera.exe`). They are normally generated by the automatic updater —
see [Data updater](data-updater.md) — but they are plain JSON and can be repaired by hand if the
updater cannot run.

| File | Contents | Used by |
| --- | --- | --- |
| `weapons.json` | Every weapon name, GOOD-normalized | `WeaponScraper` |
| `artifacts.json` | Every artifact set with its five pieces | `ArtifactScraper` |
| `characters.json` | Every playable character with element, constellation, weapon type | `CharacterScraper` |
| `materials.json` | Scannable material and development item names | `MaterialScraper` |
| `version.txt` | Game data version the tables were generated from | updater |

## Conventions common to all files

- Names are stored in **PascalCase** with all non-alphanumeric characters removed
  (`Traveler's Sword` → `TravelersSword`). This matches the
  [GOOD](https://frzyc.github.io/genshin-optimizer/good) naming scheme.
- Keys are the lowercase form of the value (`"travelerssword": "TravelersSword"`).
- Keep the JSON valid — run it through a validator such as
  [jsonlint.com](https://jsonlint.com/) after manual edits.

## weapons.json / materials.json

Simple string dictionaries:

```json
{
  "dullblade": "DullBlade",
  "amosbow": "AmosBow"
}
```

`materials.json` has the same shape (`"mora": "Mora"`, `"mysticenhancementore": "MysticEnhancementOre"`, …).

## characters.json

Each value is an object with the character's GOOD name, element(s), constellation name(s), the
order in which constellation levels 3/5 land (skill vs. burst), and a weapon type id.

```json
"albedo": {
  "GOOD": "Albedo",
  "ConstellationName": ["Princeps Cretaceus"],
  "ConstellationOrder": ["skill", "burst"],
  "Element": ["geo"],
  "WeaponType": 0
}
```

Weapon type ids:

| Value | Weapon |
| --- | --- |
| 0 | Sword |
| 1 | Claymore |
| 2 | Polearm |
| 3 | Bow |
| 4 | Catalyst |

### Traveler

The Traveler is one entry with every unlocked element and a per-element constellation order, because
the C3 upgrade target differs by element:

```json
"traveler": {
  "GOOD": "Traveler",
  "Element": ["electro", "pyro", "dendro", "geo", "hydro", "anemo"],
  "ConstellationOrder": {
    "electro": ["burst", "skill"],
    "pyro": ["skill", "burst"],
    "dendro": ["skill", "burst"],
    "geo": ["burst", "skill"],
    "hydro": ["skill", "burst"],
    "anemo": ["burst", "skill"]
  },
  "WeaponType": 0
}
```

### Constellation name and order

- `ConstellationName` is the name of the character's constellation as shown in-game. It is an array
  because a handful of entries (the Traveler's male/female variants) have more than one.
- `ConstellationOrder` records what the **third** constellation upgrades: `["skill", "burst"]` means
  C3 improves the elemental skill, `["burst", "skill"]` means it improves the elemental burst.
  (The fifth constellation upgrades the other one.) The character screen shows these levels, and the
  scanner uses this to interpret them.

## artifacts.json

Sets are keyed by lowercase set name. Each set lists its five pieces with their in-game names and
GOOD forms:

```json
"adventurer": {
  "setName": "Adventurer",
  "GOOD": "Adventurer",
  "normalizedName": "adventurer",
  "artifacts": {
    "flower":  { "artifactName": "Adventurer's Flower",     "GOOD": "AdventurersFlower",     "normalizedName": "adventurersflower" },
    "plume":   { "artifactName": "Adventurer's Tail Feather", "GOOD": "AdventurersTailFeather", "normalizedName": "adventurerstailfeather" },
    "sands":   { "artifactName": "Adventurer's Pocket Watch", "GOOD": "AdventurersPocketWatch", "normalizedName": "adventurerspocketwatch" },
    "goblet":  { "artifactName": "Adventurer's Golden Goblet", "GOOD": "AdventurersGoldenGoblet", "normalizedName": "adventurersgoldengoblet" },
    "circlet": { "artifactName": "Adventurer's Bandana",     "GOOD": "AdventurersBandana",    "normalizedName": "adventurersbandana" }
  }
}
```

Slot keys are fixed: `flower`, `plume`, `sands`, `goblet`, `circlet`.

## After manual edits

- The scanner loads these files at scan start; restart the scan (no app restart needed) to pick up
  changes.
- If a scanned item is rejected with a screenshot in `logging/<category>/`, the first suspect is a
  name missing from the table or a version mismatch (`version.txt` older than your game).
- The updater will overwrite manual edits the next time it detects a new version — if you intend to
  keep hand fixes, also update the upstream data or disable automatic updates.
